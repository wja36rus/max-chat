# MAX Chat — GREEN-API

Веб-чат для мессенджера [MAX](https://web.max.ru/) на базе [GREEN-API](https://green-api.com/max). Текстовые сообщения, минимальный интерфейс, чистый React без бэкенда.

## Требования задания

| Требование                     | Реализация                                                           |
| ------------------------------ | -------------------------------------------------------------------- |
| Отправка сообщений в MAX       | `POST waInstance{id}/sendMessage/{token}` (`src/greenApi.js`)        |
| Приём сообщений из MAX         | HTTP API: поллинг `receiveNotification` + `deleteNotification`       |
| Только текстовые сообщения     | Фильтр `typeMessage == "textMessage"`                                |
| React                          | Vite 5 + React 18                                                    |
| Визуальная ссылка — web.max.ru | Светлая тема, фиолетовый градиент, список чатов слева, бабблы справа |

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
```

Продакшен-сборка и тесты:

```bash
npm run build
npm test           # node --test, без тест-фреймворка
```

## Как пользоваться

1. Откройте приложение, введите **idInstance** и **apiTokenInstance** из кабинета GREEN-API (аккаунт MAX должен быть авторизован — проверяется через `getStateInstance`).
2. Введите номер телефона собеседника (например, `89991234567`) — приложение проверит номер через `CheckAccount` и создаст чат. Номер должен быть зарегистрирован в MAX (РФ/РБ).
3. Напишите сообщение и нажмите Enter. Собеседник увидит его в MAX, его ответ появится в чате автоматически (поллинг раз в 1.5 с).
4. Список открытых чатов (id/телефоны, без истории) хранится в sessionStorage и восстанавливается при загрузке страницы: имена обновляются через `getContactInfo`, для «мёртвых» chatId номер перепроверяется `CheckAccount`. История сообщений каждого открытого чата подгружается через `GetChatHistory` (по 100 сообщений, ~1.2 с между чатами — лимит 1 запр/с).

## Архитектура

- `src/App.jsx` — весь UI: экран логина, список чатов, окно диалога, композер.
- `src/greenApi.js` — клиент GREEN-API + чистые функции (парсинг, нормализация, мутации чатов) — всё покрыто `test/greenApi.test.mjs`.
- Уведомления обрабатываются по схеме FIFO: `receiveNotification` → парсинг → `deleteNotification`. Дубликаты отфильтровываются по `idMessage`, исходящие webhook-и игнорируются.
- Креды живут только в localStorage (`max-chat.credentials`); список открытых чатов — в sessionStorage (`max-chat.chats.<idInstance>`), только id/телефон/имя, без истории сообщений.

## Важно

- Прямой fetch из браузера — осознанное решение без бэкенда: официальный подход GREEN-API
  (их HTML SDK работает прямо из браузера). Если API отвечает 403 на Origin — добавьте
  домен приложения (например, `http://localhost:5173` для разработки) в список разрешённых
  origin-ов в настройках инстанса (личный кабинет GREEN-API → «Настройка»/«Modify settings»).
- Если CORS всё ещё мешает, можно добавить dev-прокси в `vite.config.js`:

  ```js
  server: {
    proxy: {
      "/api": { target: "https://api.green-api.com", changeOrigin: true, rewrite: (p) => p.replace(/^\/api/, "") },
    },
  },
  ```

  и заменить `API_URL` на `"/api"`.

- `GetChatHistory` (по 100 сообщений на чат при загрузке) имеет лимит **1 запр/с** — приложение
  растягивает загрузку истории открытых чатов на ~1.2 с между чатами. При 429/466 история
  пропускается молча: живые сообщения всё равно приходят через поллинг.
- Поллинг `receiveNotification`/`deleteNotification` работает по схеме FIFO-очереди и не
  перезагружает страницу: новые сообщения дописываются в открытый чат без сброса интерфейса.

- В MAX `chatId` — это числовой идентификатор аккаунта (например, `10000000@c.us`), а не номер
  телефона. Номер в `chatId` превращает метод `CheckAccount` (`POST .../checkAccount/{token}`,
  тело `{"phoneNumber": 79991234567}`), который возвращает `{"exist": true, "chatId": "10000000"}`.
  Отправка на номер, за которым нет аккаунта MAX, возвращает ошибку `noAccount` во входящем вебхуке.
- GREEN-API.MAX принимает только номера РФ (`7`) и РБ (`375`).
- Тариф «Разработчик» ограничен помесячной квотой: лимит вызовов по методам и **лимит чатов (по умолчанию 3/мес)**. При превышении API отвечает кодом **466** (`invokeStatus` — по методам, `correspondentsStatus` — по чатам), а в поллинг приходит вебхук `quotaExceeded`. Важно: отправитель `phoneNumber@c.us` и `chatId` считаются **разными чатами** в квоте — используйте единый формат (после решения через `CheckAccount` — только `chatId`). Приложение показывает понятное сообщение вместо голого 466.
